| Field | Value |
|---|---|
| Objective | Install the minimum guardrails so builders can work without redefining "done" |
| Owner / builder | D. **A human does the installing.** An agent may only help read and check |

| Stronger review required? | Optional. This planning pass examined the design but did not approve it |

## Scope
Install what [APPLY.md](../drafts/BS-00/APPLY.md) lists: verifier, manifest and admin tools, pins, hook and deny rules,
agent definitions, the Agent-tool and SubagentStop hooks, campaign approval and the guarded stage commit, invariant tests, acceptance tests, git pre-commit hook.

## Explicit exclusions
No application changes: the launcher fix is SW-00's job. No hardware. No CI. No extra framework.

## Allowed edits
Human: anything APPLY.md names. Agents: none on live protected paths.

## Pre-approved commands and runs
Only those in APPLY.md, run by the human. **Running the verifier for the negative tests in APPLY.md section 5 is
pre-approved for this contract, on the throwaway branch `codex/SW-01`, using at most the 4 counted attempts authorized
there, plus runs that stop before counting an attempt.** This does not authorize any verifier run for real SW-01 work.

## Acceptance
All from APPLY.md section 5, recorded in `docs/evidence/BS-00/install-log.md`:
- `tests/test_core.py` and `tests/test_guardrail_invariants.py` pass in the core `.venv` (17 tests) with the real scikit-learn and joblib; a stubbed run is diagnostic only.
- `guardrail_admin.py status` lists the approved campaign DEMO-1 after the one-time approval (APPLY 6.2).
- A hook or deny rule blocks a Claude edit of `tests/test_core.py`, a Claude `git push`, and a Claude `git commit`.
- `tools/work_identity.py` reports a different identity after each edit, new file or deletion of an uncommitted path, equal identities for equal content, and a failing `gate` while verify and the required reviews are absent.
- The verifier reports TAMPER for a changed protected file and a changed pin, BLOCKED when unauthorized or a module is missing, WRONG BRANCH on another branch, and FAIL for acceptance tests that are still red.

## Hardware and manual checks
None.

## Risks
Setup eats build time; hook false positives; hook and pre-commit differ between Windows and other machines.

## Stop conditions
At 45 minutes, install only the verifier, manifest and deny rules, and record what was skipped in `TODO.md`. Do not
continue tuning.

## Handoff and close
Human commits by explicit path to `codex/BS-00`, merges to local `main` for the negative tests, and commits the install
evidence locally. **That is local acceptance; the campaign prompt (prompt pack section 0, for DEMO-1) may start from
local `main` without any push.** Pushing `main` is a separate, optional, human-only publishing step that distributes the
accepted guardrails; each teammate then pulls and runs `guardrail_admin.py anchor` in their own clone. Agents never push
or merge. Nothing in this contract approves any application change.
