## Scope
**Already in the baseline (`7a9e315`; teammate-reported, not independently verified on hardware).** Topic `forge/control/reset` with payload `{ts}`.
`Brain.on_reset` clears `persons`, `avoid` and `cooldown`. `Dashboard` clears events, zones, dispatches and log (the log keeps a
`(reset)` marker), and the R key publishes a reset. `pi/reset.py` is the command-line sender. **Keep all of this.**

Remaining work, extending that code:
1. **Payload stays compatible.** Handlers accept `{ts}` alone. Optional `reason` and `operator` are additive and never required.
2. **One canonical sender: `pi/reset.py`.** Move its work into `send_reset(bus, reason=None, operator=None)` behind `if __name__ == "__main__":`
   (importing it must publish nothing) and add `--reason` and `--operator`. No `demo_ctl.py`. The dashboard R key may keep publishing `{ts}`.
3. **New topic** `forge/status`: `{ts, service, level, msg}`, level `INFO`, `WARN` or `ERROR`. `Brain` publishes an `INFO` status once its reset has run.
   `reset.py` waits up to 2 s after sending, prints which services acknowledged, and exits non-zero if the brain did not (the completion report).
4. `Brain` keeps `scan`, `model` and the event ID counter on reset (already true).
5. `ChangeDetector.reset()` clears `tracks`. `lidar_node.py` subscribes to `forge/control/reset`, calls it, and publishes a `forge/status` line.
   (Open: today a box left in the scene never re-fires after reset.)
6. **Zone dedupe.** `MARK_AVOID` for the same kind within `AVOID_RADIUS_M` updates that zone (`ts`, plus new `count`, `first_ts`). No time-based expiry. (Open: `brain.py` still appends every time.)
7. Bring `bus.py` docs up to date, including `forge/control/reset`, `forge/status`, `avoid_zones` and `forge/drone/status`.

## Explicit exclusions
No automatic expiry to simplify the demo. No resetting the LiDAR baseline file. No recalling a drone. No change to `decide()`. No second reset interface or launcher.
