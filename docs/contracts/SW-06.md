## Scope
**Already in the baseline (`7a9e315`).** `run_pi.sh` modes `hw` (default), `sim`, `fly`, `baseline`; one log per module under `logs/`;
the `FORGE_MQTT_HOST` override in `pi/config.py`; `mac/sync_to_pi.sh` and `mac/dashboard.sh`. Teammates report it working on the Pi;
that is **not independently recorded**. Keep all of it. There is no `run_demo.py`.

Gaps in the baseline launcher, which this contract closes:
1. `run_pi.sh` prints "started" without checking the child. Add a readiness check (`kill -0` after a short delay) and a loop that reports when a
   child later exits, naming it and its log. No auto-restart, no systemd.
2. `pi/preflight.py`: `Check(name, status, detail)`, `run_checks(live, model_file, baseline_file, broker_probe, serial_ports)`, `exit_code(checks)`, and a
   CLI `python pi/preflight.py --check --sim|--live` that prints a table and exits non-zero on FAIL. Names include `mqtt_broker`, `lidar_baseline`, `node_model`. `run_pi.sh` calls it before starting.
3. **No silent placeholder model.** `run_pi.sh` today trains a synthetic model if none exists, even in `hw` and `fly` modes. Replace that with a visible
   WARN (`node_model`) in live modes. A synthetic model is allowed only in `sim` mode and is labelled SIM.
4. `config`: data paths become absolute under `pi/`; add `FORGE_MQTT_PORT` beside the existing `FORGE_MQTT_HOST`. Keep `FORGE_MQTT_HOST` semantics and the `localhost` default.
5. `Brain.main` survives any model load failure, including a missing module, and publishes or prints the reason.
6. Broker connection failure prints a clear message, not a stack trace.
7. Dashboard health strip from `forge/status`, showing each source LIVE or SIM.
8. **Flight stays out of the launcher's convenience path.** `run_pi.sh fly` must not pass `--force` (SW-00 test, which stays in the regression set). Until SW-08 is applied, live flight needs a
   human edit of `DRONE_DRY_RUN`. After SW-08, `fly` mode also asks for typed confirmation from a person at the terminal (drafted in SW-08, not here).
9. README: document Mosquitto's network listener (check on the Pi first), the `.venv` setup, the launcher, and the Windows laptop workflow in
   [LAPTOP_WINDOWS.md](../LAPTOP_WINDOWS.md). Keep `mac/dashboard.sh`; do not add a second dashboard launcher for the same job.

## Explicit exclusions
No systemd. No auto-restart loops. No Docker. No new launcher beside `run_pi.sh`, and no `run_demo.py`. Camera pipeline start stays a documented separate command until HW-B3 proves it. No change to `drone_dispatch.py` (protected; SW-08).
