## Scope
1. `pi/recon.py`: pure `recommend(zones, events, avoid_zones, now, person_max_age_s)`, returning a list sorted by rank with `zone`, `rank`, `recommendation`, `reasons`, and `evidence` entries such as `{"source": "live:person", "event_id": 7}` or `{"source": "cached:prediction", "sample_id": "..."}`. The rule table is in the feasibility plan section 8.
2. `ReconService(bus, clock=time.time)`: subscribes to context, events, actions (for `avoid_zones`) and reset. Publishes `forge/recon/recommendation` `{ts, recommendations: [...], context_status}`. Reset drops live evidence and keeps the prior.
3. Dashboard panel: ranked list, with reasons and LIVE or CACHED beside each.
4. `run_pi.sh` starts it when context files exist. It is optional: if the service fails, the launcher reports it and every other service keeps running. The live demo never waits on it.

## Explicit exclusions
No publishing to `forge/action`. No editing `avoid_zones`. No calling `decide()`. **`brain.py` and `policy.py` stay unaware of it.** Nothing here dispatches.
